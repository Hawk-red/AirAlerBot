## 1. Что это и где

Бот воздушных тревог для **Киева и Киевской области**. Читает официальный
Telegram-канал Воздушных сил ВСУ **@kpszsu**, фильтрует сообщения по географии
и типу угрозы, переводит на русский и рассылает подписчикам через своего
Telegram-бота.

| Параметр | Значение |
| --- | --- |
| Машина | **только Mac Mini** (прода/второй копии у бота нет) |
| Папка | `/opt/alert_monitor` |
| Git remote | `git@github.com:Hawk-red/AirAlerBot.git`, ветка **master** |
| Владелец файлов | `hawk` |
| Python | 3.12.3 в `venv/`, Telethon 1.35.0 |

На GitHub уходит **только код**: `config.json` с токенами в `.gitignore`.

Две независимые сетевые связи:
- **чтение** канала — MTProto через Telethon, от имени **личного аккаунта**
  (userbot-сессия `alert_monitor.session`), а не бота;
- **отправка** подписчикам — HTTPS Bot API через `urllib`, без зависимостей.

## 2. Как запускать и тестировать (КРИТИЧНО — экономит время)

**Только через venv:**

```bash
cd /opt/alert_monitor
./venv/bin/python3 main.py --test-title "текст"
```

Системный `python3` падает с `ModuleNotFoundError: No module named 'telethon'` —
telethon стоит только в venv. На этом теряется время каждый раз.

| Команда | Что делает |
| --- | --- |
| `./venv/bin/python3 main.py --test-title "текст"` | перешлётся ли, какой **заголовок**, причина, тип и **тело сообщения целиком** |
| `/test <текст>` в самом боте в Telegram | проверка на живом фильтре, не трогая сервер |
| `./venv/bin/python3 main.py --test-bot` | тестовая рассылка всем подписчикам (осторожно — реально уйдёт людям) |
| `python3 -m py_compile main.py` | синтаксис (годится и системный python) |

**`--test-filter` — УСТАРЕЛО.** Она вызывает `check_message_match()` по списку
`config.keywords` — это мёртвая легаси-логика, дублирующая `cities`, и к реальному
фильтру `should_forward()` отношения не имеет. В README про неё написано ошибочно.
**Не использовать и не верить её ответу.** Если трогаешь — чинить (перевести на
`should_forward`) или явно пометить «устарело», но не удалять молча (см. раздел 11).

## 3. Служба и перезапуск

```
alert_monitor.service   User=hawk   Restart=always   RestartSec=5
WorkingDirectory=/opt/alert_monitor
ExecStart=/opt/alert_monitor/venv/bin/python3 main.py
```

Перезапуск и проверка:

```bash
sudo systemctl restart alert_monitor && systemctl is-active alert_monitor
journalctl -u alert_monitor -n 50 --no-pager      # или tail -f alert_monitor.log
```

**sudo-пароль** отдавать **пользователю** готовым блоком, не подставлять в команды
молча. Если пароль не подходит — **остановиться и спросить**, не подбирать.

> **ВАЖНО: правки `config.json` вступают в силу ТОЛЬКО после перезапуска.**
> Конфиг читается один раз при старте (`load_config()` в начале `main()`).
> На этом ловились много раз: поменяли список городов, проверяют — «не работает».

## 4. Карта кода (где что менять)

| Функция | Отвечает за |
| --- | --- |
| `should_forward(text, config)` | **пересылать или нет**; возвращает `(bool, match_reason)` |
| `classify_message_kind(text)` | `report` (сводка) / `news` (некролог, статистика) / `None` |
| `build_alert_title(text, match_reason)` | **заголовок** + причина по-русски + стрелка направления |
| `build_alert_message(...)` | **тело** сообщения; здесь замена ☄️→🚀 и однострочный отбой |
| `translate_to_ru(text)` | локальный словарь замен (раздел 7) |
| `get_direction_arrow(t)` | стрелка «откуда летит» по тексту |
| `poll_channel(...)` | **ЕДИНСТВЕННАЯ точка отправки**; опрос канала каждые 7 сек через `get_messages(min_id=last_id, limit=50)` |
| `poll_bot_updates(config)` | команды бота `/start`, `/stop`, `/test`; `getUpdates` каждые 3 сек |
| `send_telegram_bot_message_to_all(text, config)` | рассылка; при HTTP 403/400 подписчик удаляется |

**Push-обработчик `events.NewMessage` — ТОЛЬКО диагностика задержки, он НЕ шлёт.**
Это осознанное решение: отправка перенесена в `poll_channel`, чтобы переживать
разрывы связи. Не «чинить», добавляя туда отправку — получишь дубли.

Поток: канал → `poll_channel` → `should_forward` → `build_alert_title` →
`translate_to_ru` → `build_alert_message` → `send_telegram_bot_message_to_all` →
запись `last_id.txt`.

## 5. Главные грабли (прочитать перед любой правкой)

### 5.1. Протокол `match_reason` — строковый
`should_forward` возвращает **строку**: `"моє місто: київ"`, `"швидка загроза: ракет"`,
`"відбій швидкої загрози"`, `"відбій (київ)"`, `"загальнонаціональна"`,
`"дрон, місто Київ: шахед"`. `build_alert_title` и `build_alert_message` разбирают
её **поиском подстроки**.

Переименуешь строку в одной функции — заголовок **молча** свалится в ветку `else`
(`🛸 БпЛА`), а отбой перестанет быть однострочным. `py_compile` и импорт этого не
поймают. **Строки причин менять только синхронно во всех местах.**

### 5.2. Порядок веток в `should_forward` критичен
```
відбій → дроны → моє місто → national → швидка загроза → остальные дроны
```
Дроны проверяются **ДО** «моє місто»: иначе подстроки `київщ`, `бровар`, `борисп`
в `cities` перехватят дрон, летящий мимо Киева на область. **Не переставлять.**

### 5.3. География и маркеры живут в ТРЁХ местах
| Что | Где |
| --- | --- |
| города/регионы | `config.json`: `cities`, `keep_cities`, `far_regions`, `far_cities`, `far_directions` |
| они же | кортежи внутри `should_forward` (фильтр дронов: `київщ`, `бровар`, `борисп`…) |
| они же | `oblast_markers` в `build_alert_title` |
| ракетные слова | `config.fast_threats`, `rocket_markers` и `takeoff_markers` в `build_alert_title`, `FAST_ALL_CLEAR_MARKERS` для отбоя |

**Правка только в `config.json` даст эффект в фильтре, но НЕ в заголовке.**
Добавляя город или носитель — пройти по всем трём местам.

### 5.4. Регекс Киева продублирован
`\bки[їіє]в(а|у|і|ом)?\b` встречается в `should_forward` (фильтр дронов) и в
`build_alert_title`. Меняешь — меняй в обоих.

### 5.5. Прочее
- `ALL_CLEAR_MAX_LEN = 160` страхует отбой от длинных сводок — не поднимать без нужды.
- Порог `hits >= 2` в `classify_message_kind` выверен по логам (у настоящих сводок
  2–9 маркеров, ровно с одним не бывает). Не снижать до 1.
- `config.keywords` **не используется** реальным фильтром, хотя пишется в лог при
  старте как «Список отслеживаемых ключевых слов» — не путаться.

## 6. Логика фильтра и шкала заголовков (текущее состояние)

**Что пересылается:**
- **свой город/область** (`cities`) — всегда, приоритет над далёкими регионами;
- **общенациональное** (`national`: «по всій україні», «масован») — всегда;
- **быстрые угрозы** (баллистика, ракеты, МіГ-31, аэробаллистика) — всегда,
  **кроме** далёкого региона (`far_regions`), далёкого города (`far_cities`,
  если рядом нет нашего пригорода из `keep_cities`) и далёкого направления
  (`far_directions`);
- **дроны/шахеды/БпЛА** — **только если в тексте само місто Київ** по регексу
  (не «Київщина», не пригород); если Киев упомянут как ориентир («східніше Києва»),
  а цель — область, сообщение глушится;
- **отбой быстрой угрозы** («Відбій загрози застосування балістичного озброєння») —
  всегда, даже без города: канал даёт такой отбой без географии. Ограничения:
  длина ≤ 160 символов, есть маркер носителя, нет далёкого региона/города/направления;
- **отбой по своему городу** — всегда.

**Шкала заголовков по срочности (сверху — счёт на минуты):**

| Заголовок | Когда | Запас времени |
| --- | --- | --- |
| 🚨 🚀 **РАКЕТА НА КИЕВ — В УКРЫТИЕ!** ‼️ | баллистика/ракета + явно Киев | 1–2 минуты |
| 🚨 **Угроза — Киев** / **Киевская область** | город/область без ракетных слов | минуты |
| 🚀 **РАКЕТА** | реальный пуск, быстрая угроза без слов «загроза застосування» | минуты |
| 🚀 **Возможны пуски ракет** | заявлена угроза/риск применения | десятки минут |
| ⚠️ **Угроза! Взлёт носителей ракет** 🚀 | взлёт Ту-95/Ту-160/Ту-22, стратеги | часы |
| 🚨 **Тревога — вся Украина** | общенациональное | — |
| 🛸 **БпЛА** | дроны (прошедшие фильтр) | — |
| 🟢 **Отбой…** | відбій | — |
| 📊 **Сводка (за ночь)** | отчёт о прошедшей атаке | не срочно |
| 📰 **Новость** | некролог, награждение, месячная статистика | не срочно |

К заголовку добавляется **стрелка направления** (откуда летит), кроме сводок,
новостей, отбоев и общенациональных тревог.

## 7. Перевод

`translate_to_ru()` — **локальный словарь** (~60 пар), **без сети**. Заменяются
известные корни и падежные формы, остальной украинский остаётся как есть — это
допустимо и читаемо.

Google Translate (`translate.googleapis.com`) убран 30.08.2026: стабильно отдавал
**429 Too Many Requests**. Старый код оставлен закомментированным как память.

> **НЕ возвращать сетевой перевод в критический путь.** В момент тревоги сеть —
> это задержка или потеря сообщения. Новые слова просто **добавлять в словарь**
> (ключи сортируются по длине, длинные применяются первыми — порядок в коде не важен).

## 9. Процесс правки (как мы работаем)

1. **Проверить, что сервис жив:** `systemctl is-active alert_monitor`.
2. **Показать текущий код** того места, которое меняем (не править вслепую).
3. **Изменить.**
4. **`python3 -m py_compile main.py`.**
5. **Прогон на реальных примерах** — `--test-title` на 2–3 характерных текстах,
   включая соседние типы сообщений (не сломался ли тот, кого не трогали).
6. **Для правок фильтра/заголовков — golden-set:** `./venv/bin/python3 golden_test.py`.
   Расхождения должны быть **только ожидаемые** (ровно те сообщения, ради которых
   правили). Неожиданное расхождение = регрессия, разбираться до коммита.
   После того как изменения **подтверждены пользователем** — **переснять эталон**:
   `./venv/bin/python3 golden_test.py --generate` и закоммитить обновлённый
   `golden.json` вместе с правкой.
7. **Показать `git diff`.**
8. **Перезапуск** + проверка `is-active` и логов.
9. **Коммит и push.**

Правила:
- **Не коммитить без подтверждения пользователя.**
- Для правок **фильтров и заголовков — ОБЯЗАТЕЛЬНО `golden_test.py`** (раздел 6
  процесса выше). Он собирает корпус из `alert_monitor.log*` (тысячи реальных
  сообщений) и сверяет с эталоном `golden.json`, показывая было→стало. Смотреть не
  только «что стало проходить», но и **что перестало**. Эталон переснимается
  (`--generate`) только после подтверждения правок — иначе регрессия «засолится».
- **Стиль комментариев:** при изменении логики — комментарий с **датой и цифрами из
  логов**. Пример из кода:
  `# фильтр дронов 2026-08-28: дрон без ракетных слов шлём тільки якщо в тексті є саме місто Київ`
  или `# Порог 2: по логам (1421 сообщение) сообщений ровно с ОДНИМ маркером не бывает`.
  Этот стиль — главная ценность кодовой базы, **сохранять его**.
- **Коммиты — на украинском**, осмысленным сообщением (см. `git log`).

## 10. Известные ограничения (не баги, а физика и принятые решения)

- **Нет света → бот молчит.** При возврате бэклог **НЕ рассылается как живые
  тревоги** — ✅ **СДЕЛАНО 29.10.2026**: отсечка по возрасту сообщения.
  Сообщения старше `MAX_AGE_SEC = 300` сек (5 мин) не отправляются, в лог пишется
  `⏳`, `last_id` двигается. Константа — наверху `main.py`, рядом с
  `ALL_CLEAR_MAX_LEN`; сама проверка — в `poll_channel`, после вычисления `lag`,
  до `should_forward` (поэтому golden-set её не видит). Порог менять там же.
- **Один источник (@kpszsu)** — единая точка отказа.
- **Правки сообщений в канале не отслеживаются:** `min_id` не вернёт
  отредактированное старое сообщение.
- **Нет ретраев отправки** — сетевой сбой в момент тревоги = тревога потеряна.
  **Нет детектора тишины** — если userbot-сессия отвалится, процесс останется
  `active`, а тревог не будет, и никто не узнает. Оба фикса запланированы.
- Задержка доставки: **98 % сообщений < 10 секунд** (по логам), остальное —
  последствия перезапусков и разрывов связи.

## 11. Чего НЕ делать

- **Переписывать с нуля**, переводить на `aiogram` / `python-telegram-bot`.
  Система отлажена месяцами боевой работы, каждая ветка фильтра оплачена реальной
  ошибкой (ложная тревога, пропущенный отбой). Переписывание обнулит это знание.
  Нужна **эволюция**, не революция.
- **Сетевой перевод** (Google, LLM) в критическом пути — уже наступали, 429.
- **Webhook** вместо long-poll — нет публичного порта и TLS (роутер не отдаёт 80).
- **БД вместо json/txt** — два подписчика и один `last_id` не стоят SQLite.
- **ML/LLM-классификация** сообщений вместо маркеров — недетерминированно и
  непроверяемо, для тревог неприемлемо.
- **Молча удалять `--test-filter`** — она описана в README; чинить или пометить
  «устарело».
- **Снижать пороги** (`hits >= 2`, `ALL_CLEAR_MAX_LEN = 160`) без прогона по логам.
